파서가 콘텐츠를 잃지 않기까지

낯선 XML을 버리던 파서가 무손실 보존, 확장 API, 안전 제한, 시각 매크로까지 갖추는 과정을 직접 탐색해 보세요.

2026년 9월 19일약 9분인터랙티브 도표 5개

출발점: 보이지 않는 손실

Confluence 문서를 열었는데 표의 한 구역, 앱 매크로, 링크 본문이 조용히 사라진다면 결과 HTML은 그럴듯해도 원본을 믿고 옮겼다고 말할 수 없습니다.

이 프로젝트의 첫 번째 기준은 화려한 렌더링이 아니었습니다. 파서가 이해하지 못하는 콘텐츠도 버리지 않는 것이었습니다. 체크리스트는 이 기준을 세 마일스톤으로 나눴습니다. 첫 단계는 보존 모델, 두 번째는 공개 확장 API와 안전 제한, 세 번째는 PlantUML과 레거시 탭처럼 선택적으로 활성화하는 어댑터입니다. 이후 품질 게이트와 웹 렌더러 작업이 이어졌습니다.

마일스톤 1: 먼저, 버리지 않는다

GenericElement와 GenericMacro는 파서가 모르는 입력을 막다른 골목이 아니라 보존 가능한 데이터로 바꿉니다.

무손실 경로에는 네임스페이스, 속성, 자식 노드, 매크로 매개변수와 본문 종류가 남습니다. 표의 thead, tbody, tfoot도 타입으로 구분됩니다. 동시에 진단은 문자열 호환성을 유지하면서 심각도와 XML 경로를 가진 구조화된 정보가 됐습니다. 이 조합 덕분에 소비자는 문제를 보고하면서도 원본 하위 트리를 계속 다룰 수 있습니다.

정책 버튼을 바꿔 보세요. 같은 알 수 없는 매크로가 preserve, error, drop에서 전혀 다른 운명을 맞습니다.

마일스톤 2: 열어 두되, 경계를 둔다

확장 가능한 파서는 입력 크기와 등록 충돌도 함께 통제해야 합니다. 문을 달았다면 잠금장치도 필요한 셈입니다.

register_macro()와 register_element()는 소비자가 전용 파서를 연결할 수 있게 합니다. 레지스트리는 인스턴스마다 격리되고 기존 이름을 덮어쓸 때는 명시적인 선택이 필요합니다. XML 크기, 깊이, 노드 수, 매개변수 수, 평문 본문 크기에 대한 제한도 같은 마일스톤에서 추가됐습니다.

아래 슬라이더는 실제 기본값을 복제하는 설정 UI가 아니라 제한이 판단에 미치는 방식을 보여주는 모형입니다. 샘플 문서는 깊이 64, 노드 1,200개라고 가정합니다. 허용치를 그 아래로 낮추면 즉시 거부 상태로 바뀝니다.

마일스톤 3: 필요한 기능만 연결한다

모든 마켓플레이스 매크로를 핵심 파서에 넣는 대신, 원본을 보존하고 확인된 형식만 선택형 어댑터로 승격했습니다.

레거시 tabs와 tab은 중첩 순서와 제목을 유지합니다. PlantUML 어댑터는 평문 다이어그램 소스를 정확히 보존합니다. 웹 서버는 이를 한 단계 더 발전시켜 탭 선택 UI와 로컬 SVG를 만들며, 위험한 include와 import 지시문은 차단합니다. draw.io는 일반 파서 모델에서는 무손실 매크로로 남고, 웹 렌더러에서는 인라인 비압축 mxGraphModel을 로컬 SVG로 표시합니다. Confluence 첨부파일만 가리키는 경우에는 resolver가 필요하다는 fallback을 보여줍니다.

버튼을 눌러 같은 저장 형식 파이프라인에 서로 다른 어댑터가 끼워지는 모습을 비교해 보세요.

품질 게이트: 체크는 테스트 뒤에

체크리스트의 규칙은 구현했다고 느끼는 순간이 아니라 관련 검증이 통과한 순간에만 완료 표시를 남기는 것입니다.

파서 쪽에는 기존 테스트, 새 테스트와 커버리지, Ruff, Black, Mypy, 편집 가능한 로컬 의존성 검증이 기록돼 있습니다. 최종 파서 실행에서는 163개 테스트가 통과했습니다. 웹 서버 쪽은 draw.io와 실행 스크립트 테스트를 더한 뒤 25개 테스트가 통과했고, 실제 포트에서 샘플 목록과 SVG 응답도 확인했습니다.
